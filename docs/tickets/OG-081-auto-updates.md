# OG-081 · In-app auto-updates

- **Milestone:** M14 — In-app auto-updates
- **Status:** done
- **Depends on:** OG-077, OG-068
- **References:** ADR-0007, `src/lib/stores/update.ts`, `src-tauri/tauri.conf.json`, `.github/workflows/release.yml`

## Context

OG-077 checks the latest GitHub release and offers a download link, but the user
still has to fetch and install the installer by hand. The wanted flow is the
SourceTree/FlupCode one: the app notices a new version, downloads the correct
artifact, and offers "Restart to install". See ADR-0007 for the decision to use
`tauri-plugin-updater` with a free minisign key instead of code signing.

## Scope

- Rust: add `tauri-plugin-updater` and `tauri-plugin-process`, register both in
  `lib.rs`; capabilities `updater:default` and `process:allow-restart`.
- `tauri.conf.json`: `bundle.createUpdaterArtifacts: true` and `plugins.updater`
  with the public key and the `releases/latest/download/latest.json` endpoint.
- Frontend: rewrite `stores/update.ts` on top of the updater plugin
  (`check`, `downloadAndInstall` with progress, `relaunch`), keeping the silent
  24h-cached startup check and the manual native-menu check.
- Replace the `UpdateNotice` banner with an `UpdateDialog` modal: "OpenGit X is
  ready / Restart to install", **Later** / **Restart now**, download progress,
  and up-to-date/error feedback for manual checks.
- Release workflow: sign updater artifacts, upload them, and generate
  `latest.json` (version, notes, date and per-platform URL + signature).
- Docs: key generation, GitHub secrets and the manual first release.

## Acceptance criteria

- [x] Starting the app checks silently (cached 24h) and, when an update exists,
  downloads it in the background without blocking the UI.
- [x] When the update is ready, a modal offers **Later** / **Restart now**;
  restarting runs the new version.
- [x] The native **Check for Updates…** item forces a check and reports
  available / up to date / error.
- [x] Offline startup stays silent and never blocks the UI.
- [x] The release workflow produces signed updater artifacts and a valid
  `latest.json` attached to the draft release (validated with `v0.6.0`).
- [x] `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm test`,
  `cargo test`, `cargo clippy --all-targets -- -D warnings` and
  `cargo fmt --check` green.

## Out of scope

- Code signing and notarization (OG-028; the updater uses minisign, not Apple/
  Windows certificates).
- Intel macOS and Linux `.deb` auto-update (manual download remains).
- Beta/prerelease channels and rollback.

## Technical notes

- Dependencies are the official Tauri plugins; justified in ADR-0007.
- `latest.json` is generated by `scripts/generate-latest-json.mjs` from the
  `.sig` files, without new runtime dependencies.
- Windows exits the app automatically when it installs; OpenGit has no unsaved
  state beyond the commit message, so it is acceptable.
- The first release with the updater is installed manually; auto-updates apply
  from that version onward.

## Implementation notes (2026-09-20)

- Rust: `tauri-plugin-updater` + `tauri-plugin-process` registered in `lib.rs`;
  capabilities `updater:default` and `process:allow-restart`;
  `bundle.createUpdaterArtifacts` and `plugins.updater` in `tauri.conf.json`
  (`pubkey` is a placeholder until the key exists — the plugin only parses it
  when verifying a download, so startup and `check()` work regardless).
- Frontend: `stores/update.ts` uses `check()`/`download()`/`install()` from the
  plugin; automatic checks are silent until a download is ready, manual ones
  show checking/progress/up-to-date/error. `UpdateDialog` replaces the
  `UpdateNotice` banner; `updates.ts` is reduced to the 24h cache.
- CI: `release.yml` signs the updater artifacts, uploads the `.sig` files and
  generates `latest.json` with `scripts/generate-latest-json.mjs` (pure mapping,
  unit-tested).
- Verified locally: `typecheck`, `lint`, `format:check`, `npm test` (61 files,
  477 tests), `cargo clippy --all-targets -D warnings`, `cargo fmt --check`.
  The manifest script was also run against a fake artifacts tree.
- Minisign key generated (`~/.tauri/opengit.key`); the public key is committed
  in `tauri.conf.json` and both `TAURI_SIGNING_PRIVATE_KEY` and
  `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` are repo secrets.
- Validated end-to-end with `v0.6.0` (2026-09-20): `release.yml` built and
  signed the updater artifacts, generated `latest.json` and created the draft;
  after publishing, `releases/latest/download/latest.json` serves `0.6.0` with
  `darwin-aarch64`, `linux-x86_64` and `windows-x86_64`. The first attempt
  failed with "Wrong password for that key" because the password secret was
  wrong; re-setting it fixed the signing.
- `v0.6.0` is the first release with the updater, so it has to be installed by
  hand; later releases auto-update. Keep an offline backup of the private key:
  losing it breaks updates for installed users.
